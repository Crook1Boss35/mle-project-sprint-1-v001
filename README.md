# MLE Project Sprint 1

Проект посвящён разработке MVP модели машинного обучения для оценки рыночной стоимости квартир.

Проект состоит из двух основных частей:

- `part1_airflow` — сбор и очистка данных с помощью Apache Airflow;
- `part2_dvc` — обучение и оценка модели машинного обучения с помощью DVC.

## Этап 1. Сбор данных с Airflow

Исходные данные находятся в таблицах:

- `public.flats`
- `public.buildings`

DAG объединяет данные о квартирах и зданиях и сохраняет результат в таблицу:

`public.flats_dataset`

Путь к DAG:

`part1_airflow/dags/prepare_flats_dataset.py`

Функция DAG:

`prepare_flats_dataset`

Основные шаги DAG:

`create_table → extract → transform → load`

## Этап 2. Очистка данных с Airflow

Анализ качества данных выполнен в Jupyter Notebook:

`part1_airflow/notebooks/data_cleaning.ipynb`

В данных были исследованы:

- явные и неявные дубликаты;
- пропуски;
- логические ошибки;
- выбросы.

Функции очистки вынесены в:

`part1_airflow/plugins/steps/cleaning.py`

Основная функция очистки:

`clean_data`

DAG очистки:

`part1_airflow/dags/clean_flats_dataset.py`

Функция DAG:

`clean_flats_dataset`

Основные шаги DAG:

`create_table → extract → transform → load`

Результат сохраняется в таблицу:

`public.flats_dataset_clean`

## Этап 3. DVC-пайплайн обучения модели

DVC-пайплайн состоит из трёх этапов:

`get_data → fit_model → evaluate_model`

Python-код этапов находится в:

- `part2_dvc/scripts/data.py` — получение очищенных данных из PostgreSQL;
- `part2_dvc/scripts/fit.py` — разделение данных на обучающую и тестовую выборки, предобработка признаков и обучение модели;
- `part2_dvc/scripts/evaluate.py` — оценка модели на тестовой выборке.

Конфигурация DVC-пайплайна:

- `part2_dvc/dvc.yaml`
- `part2_dvc/params.yaml`
- `part2_dvc/dvc.lock`

Запуск полного пайплайна:

```bash
cd part2_dvc
dvc repro
```

## Модель

Для решения задачи регрессии используется:

`CatBoostRegressor`

Предобработка признаков и модель объединены в единый `sklearn Pipeline`.

Данные разделяются на обучающую и тестовую выборки со следующими параметрами:

- `test_size = 0.2`
- `random_state = 42`

Обученная модель:

`part2_dvc/models/fitted_model.pkl`

## Эксперимент с признаками

Сначала была обучена базовая версия модели, в которой:

- `building_id` использовался как числовой признак;
- `building_type_int` также обрабатывался как числовой признак.

Метрики базовой модели:

- MAE: `3196720.351`
- RMSE: `6895443.022`
- R²: `0.885`
- размер тестовой выборки: `26186`

После анализа признаков была проверена следующая гипотеза:

- `building_id` исключён как технический идентификатор здания;
- `building_type_int`, представляющий тип здания, переведён в категориальные признаки и обрабатывается с помощью `OneHotEncoder`.

Метрики итоговой модели:

- MAE: `3183070.235`
- RMSE: `6641651.003`
- R²: `0.894`
- размер тестовой выборки: `26186`

По сравнению с базовой моделью:

- MAE уменьшился на `13650.116`;
- RMSE уменьшился на `253792.019`;
- R² увеличился на `0.009`.

Итоговый вариант модели используется как финальный.
